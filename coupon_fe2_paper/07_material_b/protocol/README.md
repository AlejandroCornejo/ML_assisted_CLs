# Protocol and current code map

This folder contains the reproducible rules and current preparation pipeline.
It is not a collection of alternative experiments.

## Read first

1. [`DATA_PROTOCOL.md`](DATA_PROTOCOL.md): data roles, domain and FOM checks.
2. [`training_recipe.json`](training_recipe.json): the **single official**
   stopping and scheduler rule. [`TRAINING_RECIPE.md`](TRAINING_RECIPE.md)
   documents the inherited frozen feature/model preparation; older stopping
   experiments are pilots, summarized in `../reports/TRAINING_PILOT_SUMMARY.md`.

Their JSON counterparts are machine-readable frozen inputs. Do not edit a
frozen JSON in place; create a versioned amendment and explain why.

## Code, in execution order

| Stage | File | Reads labels? | Purpose |
|---|---|---:|---|
| Design | `prepare_design.py` | No | Generate fixed strain coordinates and role indices |
| Plan | `run_campaign.py` | No | Divide the FOM work into restartable chunks |
| Solve | `run_data_stage.py` | Produces them | Run one FOM chunk and retain failures |
| Assemble | `assemble_campaign.py` | Yes | Verify all chunks and build the approved label file |
| Select features | `select_features.py` | Fit + reference only | Produce the common 32-feature table |
| Initialize | `training_setup.py` | Fit + reference only | Build the five model types and their exact objective |
| Official optimize | `train_material_b_official.py` | Fit + reference + validation stress | Uniform validation stopping; safety boundaries pause exactly |
| Official queue | `run_training_campaign.py` | No extra labels | Launch three concurrent workers and verify completed/review-paused states |
| Review and resume | `resume_training_campaign.py` | No extra labels | Verify all 15 pauses, back up checkpoints, approve two existing 5,000-step Adam blocks together, and resume with bounded CPU workers |
| Free closeout | `close_free_lbfgs.py` | Fit + reference + validation stress | Audited Adam-cap exception for the three Free seeds; run unchanged L-BFGS stopping and label the distinct outcome |
| Lock checkpoints | `lock_final_checkpoints.py` | No labels | Verify all 15 final reports, states and hashes; write a no-overwrite manifest |
| Final neural evaluation | `evaluate_final_models.py` | Validation in preflight; reserved test/path targets only in final run | Verify the exact lock and internal gate amendment, then evaluate all 15 models once |
| Post-evaluation QA | `audit_final_mechanics.py` | Test/path coordinates, no target responses | Check derivatives and sampled rank-one curvature without selecting models |
| Bounded robustness audit | `audit_robustness.py` | No response labels | Post-test collapse sweep and directed rank-one search; scope fixed in `ROBUSTNESS_AUDIT_INTERNAL.md` |
| Stronger directed search | `directed_search.py` | No response labels | User-requested expansion in principal stretches, governed by `DIRECTED_SEARCH_INTERNAL.md` |
| Witness FOM comparison | `check_directed_fom.py` | Produces new exploratory FOM responses | Check the selected negative Free witnesses on both meshes |

`plot_directed_search.py` renders the verified witnesses and the matched
neural responses; see `../reports/DIRECTED_SEARCH.md` for interpretation.

`plot_design.py` is a technical coordinate-coverage diagnostic. The current
reader-facing figures are generated by `../paper_evidence/build_figures.py`.

`plot_campaign_response.py` is deliberately gated: it must not read reserved
final path labels until all 15 checkpoints are locked. It is not a training
script.

`training_setup.py` performs initialization and derivative checks only. The
official runner reads no test or held-out path labels. It retains the exact
current model, optimizer, scheduler and RNG at a review boundary; such a run
has no final `model.pt`. The two older runners remain only to explain pilot
provenance, not as alternative official training recipes.

Example, from the repository root, with the existing torch interpreter:

    OMP_NUM_THREADS=2 OPENBLAS_NUM_THREADS=2 MKL_NUM_THREADS=2 \
    PYTHONPATH=coupon_fe2_paper/.pydeps:coupon_fe2_paper/07_material_b \
    /home/sares/.venv-rom/bin/python -B -m protocol.train_material_b_official \
      --model ICNN-fixed --seed 16 \
      --output coupon_fe2_paper/07_material_b/results/neural_training/icnn_fixed_seed16

After an ordinary interruption, repeat with `--resume` and the same output
path. At a review boundary, inspect the validation curve first; an approved
additional block uses `--resume --approve-next-block`, which records that
decision in the checkpoint. A completed run writes `model.pt`, `run_report.json`
and a completed run-state record. Only completed models are eligible for the
all-15-checkpoint lock; never evaluate test/path targets from an incomplete or
smoke run.

For a synchronized 15-run review, use `resume_training_campaign.py` instead of
resuming runs one by one. First run `--dry-run`; after reviewing all validation
curves, give `--reason` and `--workers` (default six). It requires every run to
be finished or paused; the paused runs must share an Adam boundary. It copies
each paused run's original checkpoint into
`results/neural_training/reviews/`, and records the approved horizon as
contiguous 5,000-step bookkeeping blocks. The default horizon is another
10,000 steps; `--target-adam-step 200000` sets the approved **safety ceiling**
to 200,000 for paused runs while leaving completed runs untouched. The
validation-plateau stop remains active, and reaching a ceiling
without it produces `needs_review`, never a completed model. The frozen recipe
and trainer files remain byte-identical, but the practical review cadence is
amended and documented in `TRAINING_REVIEW_AMENDMENT.md`. A later L-BFGS review
is a separate decision; this script refuses to extend L-BFGS calls.

The subsequent Free closeout is documented in `FREE_LBFGS_CLOSEOUT.md` and
`../results/neural_training/reviews/adam_200000_to_lbfgs/approval.json`. All
three Free runs entered L-BFGS from their best Adam-validation checkpoints
after the user stopped Adam at 200,000 steps without a plateau. Their reports
therefore say `complete_budget_limited_adam`, **not** ordinary `complete`.
L-BFGS met its original plateau rule in all three; neither this fact nor the
campaign's closeout status removes the Adam-budget limitation. The separate
internal `FINAL_EVALUATION_INTERNAL.md` amended only evaluation eligibility;
the evaluator verified the exact mixed-status lock and opened reserved test
and path targets once. The results and limitations are summarized in
`../reports/FINAL_NEURAL_EVALUATION.md`.
The verified hashes are recorded in
`../results/neural_training/final_checkpoint_manifest.json`.
